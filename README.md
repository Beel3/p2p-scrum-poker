# Scrum Poker

Внутренний веб-сервис командной оценки задач (Planning Poker). Ведущий заводит
команду в комнату, участники выбирают карты со значения `0, 0.5, 1…10`, ведущий
вручную вскрывает стол и видит сводку: медиана, среднее, разброс и число
оценивших.

Интерфейс полностью на русском. Регистрация, база данных, история и экспорт в
MVP не входят — требования зафиксированы в [`docs/ТЗ.md`](docs/ТЗ.md).

## Быстрый старт

Требуется Node.js 20.19+ (проверено на 24).

```bash
npm install          # ставит workspaces и собирает @scrum-poker/shared
npm run dev          # сервер на :3000 + Vite на :5173
```

Разработку удобнее вести на `http://localhost:5173` — Vite проксирует `/api` и
`/ws` на сервер. После `npm run build` сервер отдаёт интерфейс сам, открывайте
`http://localhost:3000`.

## Запуск одной командой (продакшен)

```bash
npm ci
npm run build
npm start            # http://localhost:3000
```

## Запуск в Docker

```bash
docker compose up -d --build
docker compose ps    # статус и healthcheck
```

Образ многостадийный: сборка трёх пакетов → production-зависимости → рантайм
под непривилегированным пользователем. Комнаты живут в памяти процесса, поэтому
перезапуск контейнера стирает активные комнаты — это ограничение MVP, а не
авария.

## Структура

```
packages/shared/     протокол, колода, схемы Zod — общие для сервера и клиента
apps/server/         Fastify + ws + Zod, комнаты в памяти, раздача статики
apps/web/            React + Vite + Tailwind
docs/ТЗ.md           техническое задание, источник требований
```

## Как устроен протокол

Одно WebSocket-соединение на `/ws`, сообщения — JSON с полем-дискриминатором `t`.

Клиент → сервер: `join`, `vote`, `unvote`, `reveal`, `reset`, `take_host`,
`leave`, `ping`.

Сервер → клиент: `joined`, `state`, `vote_ack`, `voted`, `revealed`, `reset`,
`error`, `pong`.

Правило честности: сервер никогда не отправляет значение карты никому, кроме
автора (`vote_ack`), до события `revealed`. Остальным уходит только поимённый
флаг «проголосовал».

## Текущие ограничения MVP

- состояние комнат в памяти — нет персистентности и восстановления после рестарта;
- до 16 участников и 50 активных комнат одновременно;
- 12 карт фиксированной колоды, кастомных колод нет;
- нет истории, таймера, чата и экспорта.

Всё перечисленное вынесено в следующие итерации (ТЗ, раздел 2.3).
